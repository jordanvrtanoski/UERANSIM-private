# N2 Handover (NGAP) — Phase 1/2 Design (UERANSIM)

## 1. Purpose
Define a minimal, low-refactor architecture to implement **N2-based handover** (NGAP, TS 38.413) in UERANSIM with a staged execution approach:

- **Phase 1 (MVP):** NGAP handover with **private mobility messages** carried over the existing RLS transport using `EPduType::DATA` (temporary).
- **Phase 2:** Replace private mobility with **real RRC mobility procedures** (TS 38.331) and standards-aligned transparent containers.

This document targets product owners and architects and is intended to be stable across sessions.

## 2. Scope / Assumptions
### In scope (Phase 1)
- UE is already **registered** and **CM-CONNECTED**.
- Intra-AMF mobility: both source/target gNB have an NG connection to the **same AMF**.
- Single UE handover, with ability to run **multiple handovers in parallel for different UEs**.
- One or more active PDU sessions; initial MVP may validate with **1 PDU session**.
- NGAP procedures:
  - **Handover Preparation**: `HANDOVER REQUIRED / HANDOVER REQUEST / HANDOVER REQUEST ACK / HANDOVER COMMAND`
  - **Handover Notification**: `HANDOVER NOTIFY`
  - **Path Switch**: `PATH SWITCH REQUEST / ACKNOWLEDGE / FAILURE`

### Out of scope (Phase 1)
- XnAP / Xn-based handover (TS 38.423)
- Measurement-driven triggers (we start with manual trigger via CLI)
- Data forwarding tunnels (DL/UL forwarding) beyond “no-forwarding/best-effort”
- Inter-AMF handover, DAPS, dual connectivity, reallocation-heavy mobility

## 3. References
- TS 38.413 (NGAP), clauses:
  - 8.4.1 Handover Preparation
  - 8.4.3 Handover Notification
  - 8.4.4 Path Switch Request
  - 9.2.3.* message definitions
- TS 23.502: handover procedures (N2-based, Xn-based background)

## 4. Existing UERANSIM Modules (Where This Fits)
The implementation should follow the current task/module architecture to avoid refactoring:

- gNB:
  - `nr::gnb::NgapTask` (NGAP N2)
  - `nr::gnb::GnbRlsTask` / `nr::gnb::RlsUdpTask` (radio link simulation transport)
  - `nr::gnb::GtpTask` (N3 user plane)
  - `nr::gnb::GnbCmdHandler` (CLI integration point)
- UE:
  - `nr::ue::UeRlsTask` / `nr::ue::RlsUdpTask` (radio link simulation transport)
  - `nr::ue` app/command handling (place to host Phase-1 mobility glue)

**Design rule (Phase 1):** Do not introduce a new global “handover coordinator task”. Implement the procedure as a **subsystem within `NgapTask`** and exchange only the minimum required signals with RLS/UE layers.

## 5. Key Phase Separation
### Phase 1: “NGAP correct, RRC mocked”
- NGAP messages and timers follow TS 38.413.
- UE move is executed via **private mobility PDUs** over RLS (`EPduType::DATA` payload).
- NGAP transparent containers carry a **handover token** and minimal target hints for debug/matching.

### Phase 2: “NGAP + RRC correct”
- Replace private mobility PDUs with 38.331 RRC mobility procedures.
- Replace ad-hoc container content with standards-aligned encoding while preserving the NGAP procedure plumbing.

## 6. Core Data Contracts
### 6.1 Handover Token (Correlation + Race Avoidance)
We introduce a **handover token** (nonce) per handover attempt:
- Generated by **source gNB** at HO start.
- Embedded in NGAP **Source→Target Transparent Container** so the **target gNB can store it** when it receives `HANDOVER REQUEST`.
- Provided to the UE in the Phase-1 private `HO_CMD`.
- Echoed by the UE to the target gNB in `HO_COMPLETE`.

Properties:
- Globally unique per HO attempt (not just per UE) to support multiple handovers in parallel.
- Used for **context matching and debugging**, not security.

### 6.2 Target Selection (3 identifiers)
The operator can choose a target by:
- **NCI** (`--target-nci`) — canonical
- **gNB name** (`--target-name`) — operator-friendly
- **RLS cell id** (`--target-cell-id`) — local testing convenience

Resolution rules (source gNB):
1. Prefer explicit `targetNci` if provided.
2. Else use `targetName`.
3. Else use `targetCellId`.
4. If multiple matches: fail with a disambiguation list.

Execution rules (UE):
- Prefer `targetCellId` if present (direct RLS attach), else `targetNci`, else `targetName`.
- **Phase 1 reliability note:** because UE may not always have a complete mapping from `nci/name → cellId`, the private `HO_CMD` should also carry a deterministic **RLS addressing hint** (e.g., the target gNB `linkIp` from neighbor config) so that Phase‑1 execution is not blocked by missing mapping logic. This hint is removed/ignored in Phase 2.

## 7. gNB Procedure Architecture (Minimal Refactor)
### 7.1 Where procedure logic lives
Implement HO procedure logic inside `nr::gnb::NgapTask` because it already:
- Owns UE NGAP contexts and AMF association.
- Owns NGAP receive dispatch (SCTP → PDU decode → handler).
- Is the correct place to enforce NGAP timers and cleanup.

### 7.2 New per-UE HO state (in gNB UE context)
Add `HandoverState` into the existing UE context (the structure that tracks `ranUeNgapId`, `amfUeNgapId`, streams, sessions):
- `state`: `IDLE | PREP_SENT | CMD_RCVD | EXECUTING | COMPLETED | FAILED`
- `token`, `targetSpec`
- `timers`: `TNGRELOCprep`, `TNGRELOCoverall`
- `containers`:
  - `srcToTgtContainer` (bytes, includes token)
  - `tgtToSrcContainer` (bytes, received via `HANDOVER COMMAND`)
- `targetNgapIds` (target `RAN_UE_NGAP_ID` learned during preparation, if needed)

Target gNB additionally keeps a **prepared-context map**:
- `preparedByToken[token] -> PreparedHoContext`
to match `HO_COMPLETE` arrival to the previously prepared NGAP context.

## 8. Phase-1 Private Mobility over RLS `DATA`
### 8.1 Transport choice
Use `rls::RlsPduTransmission` with `pduType = EPduType::DATA` and a private header to demultiplex HO control from “real data”.

Private message types:
- `HO_CMD` (source gNB → UE): includes token and target hints.
- `HO_COMPLETE` (UE → target gNB): includes token.
- Optional `HO_FAIL` for debug.

**Important:** This is intentionally temporary and must be isolated to simplify removal in Phase 2.

## 9. Sequence Flows (Phase 1)
### 9.1 Successful end-to-end
```text
----------------+            +-----+            +----------------+
| gNB-S (source) |            | AMF |            | gNB-T (target) |
+----------------+            +-----+            +----------------+
       |  HANDOVER REQUIRED     |                       |
       |----------------------->|                       |
       | (Target ID, Cause,     |                       |
       |  PDU session list,     |                       |
       |  Src→Tgt container w/  |                       |
       |  token)                |                       |
       |                        | HANDOVER REQUEST      |
       |                        |---------------------->|
       |                        | (forwards container)  |
       |                        |<----------------------|
       |                        | HANDOVER REQ ACK      |
       |<-----------------------|                       |
       | HANDOVER COMMAND       |                       |
       | (Tgt→Src container)    |                       |
       |---- private HO_CMD over RLS DATA -------------> UE
       |                                               |
       |                                UE attaches to target cell
       |                                               |
       |<--- private HO_COMPLETE over RLS DATA --------|
       |                        |                       |
       |                        |<-- HANDOVER NOTIFY ---|
       |                        |<-- PATH SWITCH REQ ---|
       |                        |--- PATH SWITCH ACK -->|
```

### 9.2 Preparation failure (AMF → source)
```text
gNB-S -> AMF : HANDOVER REQUIRED (start TNGRELOCprep)
AMF  -> gNB-S: HANDOVER PREPARATION FAILURE
gNB-S: stop prep timer, mark FAILED, cleanup local HO state
```

### 9.3 Token mismatch / early HO_COMPLETE arrival
```text
UE -> gNB-T : HO_COMPLETE(token=X)
gNB-T: if token not in preparedByToken:
  - log as anomaly (include source addr/cell)
  - optionally cache “unmatched complete” for a short TTL
  - otherwise ignore/reject and rely on UE retry / operator debug
```

### 9.4 Execution never completes (overall timer expiry)
```text
gNB-S receives HANDOVER COMMAND (start TNGRELOCoverall)
UE never attaches to target (no HO_COMPLETE, no evidence of success)
TNGRELOCoverall expires:
  - cancel/cleanup HO attempt (and optionally trigger NGAP cancel)
  - keep UE service continuity policy explicit (MVP can keep UE on source)
```

### 9.5 Path switch failure
```text
gNB-T -> AMF : PATH SWITCH REQUEST
AMF  -> gNB-T: PATH SWITCH REQUEST FAILURE
gNB-T: mark FAILED; release prepared/active resources; optionally notify source via debug
```

## 10. Debuggability Requirements (Phase 1 must be traceable)
To ensure problems are diagnosable without packet archaeology:

### Correlation IDs (mandatory in logs)
- Log `ueId`, `ranUeNgapId`, `amfUeNgapId` (when present), and **handover token** on every HO-related event.
- Include target selectors used (nci/name/cellId) and the resolved target spec.

### NGAP visibility
- When available, record the NGAP XER/summary already produced by the node listener, with HO token included in the container (opaque but present).

### RLS private mobility visibility
- Log private `HO_CMD` transmit and `HO_COMPLETE` receive with token + endpoints.
- Maintain counters per gNB:
  - `ho_cmd_sent`, `ho_complete_rx`, `ho_complete_unmatched`, `ho_fail_rx`

### Failure diagnostics
On failure, log:
- which timer expired (prep vs overall),
- the last NGAP message observed,
- whether `HO_CMD` was sent and whether any `HO_COMPLETE` was seen.

## 11. Parallelism, Races, and Safety
### Parallel handovers
- Allow multiple handovers in parallel for different UEs.
- Enforce “only one HO at a time per UE” in source gNB (38.413 semantics).

### Race avoidance strategy
- Use the **token** as the single joining key on target.
- Keep `preparedByToken` and per-UE HO state isolated inside the owning task’s event loop to avoid data races.
- Handle out-of-order events defensively:
  - unmatched `HO_COMPLETE` should not crash; it should be logged and optionally cached for short TTL.

### Duplicate handling
- If `HO_COMPLETE(token)` arrives twice, treat second as idempotent and log once.
